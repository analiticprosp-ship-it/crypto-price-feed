## B. First stage toward "cascade vs absorption" — NOT cluster first-hit
Source: original Tardis **observed liquidation message** stream, not CoinGlass Model2 heatmaps. Tardis `liquidations.side`: `sell` denotes liquidated long position; `buy` denotes liquidated short. Price from trades of SAME venue and instrument; vendor `local_timestamp` is capture arrival microseconds, not guaranteed exchange ordering. Fix three disjoint sessions in UTC `[06:00,12:00), [12:00,18:00), [18:00,24:00)`. For each of 8 venue/date cohorts, deterministically choose **first** BTC liquidation capture message strictly after each session start; if no such record, `NO_OBSERVED_LIQUIDATION` for that bucket; never choose largest / biggest downstream mover. Three maximum event anchors per cohort, no duplication. This preferentially samples *first* messages, not high-liquidation events or large clusters. Treat it purely as **measurement pilot**.
- As-of t0 (first liquidation capture): use last observed trade `local_timestamp <= t0` <=2 seconds old. Pre-event window `[t0-30s,t0)`: buy/sell trade quantity imbalance, 30s past-price momentum using last trade at `t0-30s`, trade count and pre-event range. No future ticks for features. Future trade prices from last observed trade at +30,+60,+300s within 2s freshness. Missing as-of -> label `MISSING_ASOF`, not zero, never forward-fill beyond 2 seconds.
- Event side is the original liquidation message `side`. Direction `sell` => downward and `buy` => upward. Define `signed_return_bps_300 = direction * 10000*(P_300/P_t0 -1)`. `maximum_directional_excursion_bps` uses **observed trades with 0 < t <= +300s**, reference price from t0 (therefore hindsight **outcome only**).
- Freeze mutually exclusive **exploratory price-behaviour proxies**, not true mechanisms: `CONTINUATION_PROXY` iff signed return at +300 >= 15bp **AND** max same-direction excursion >=20bp. `OPPOSITE_REVERSAL_PROXY` iff signed return at +300 <= -10bp (regardless of earlier excursion). `LIMITED_CONTINUATION_PROXY` iff signed return at +300 between -10bp and +5bp inclusive and max same-direction excursion <10bp. Everything else `MIXED_OR_UNCLASSIFIED`. Missing t0, +300 or zero post-event observed ticks => `MISSING_ASOF`. Proxies are **not causal cascade/absorption proof**. `LIMITED_CONTINUATION_PROXY` is not classified as true absorption because cancellations/refills and maker identity unknown.
- No trained predictor at this stage; measure event counts/quality and proxies by date/venue and BTC liquidation direction only. No “likelihood of cascade”, cluster position inference or portfolio signal. Tardis observed liquidation coverage and first-message selection is not known complete or representative. Duplicates across exchanges/cases and common global BTC news create dependence, so no binomial/naïve CI.
- No no-liquidation control initially; fixed-clock non-event candidate is NOT automatically a proven zero liquidation. Case-control matching and prior depth/volatility enhancements require a separate prereg.
