## Исполнение для перспективной проверки

Нельзя заполнить сделку задним числом по уже прошедшей цене открытия. `runner.py` использует фактически наблюдаемый mid публичного bid/ask в момент проверки, сохраняет время получения и задержку от закрытия сигнала. Если вход обнаружен позднее чем через 15 минут после закрытия, он помечается пропущенным и не исполняется даже виртуально. Поздний выход оценивается по реально наблюдаемой цене проверки. Это явно отделённый перспективный операционный вариант, а не точная копия идеального исторического next-open исполнения.

Только закрытые 4H/1D. Источник: публичный Market-Data-Only Binance API без ключей и без торговых методов. NW/ATR/regime сверены с ранее замороженным расчётом. Проверки неполных окон, пропусков, свежести, текущего времени и спреда обязательны. Недоступные данные не означают отсутствие сигналов.

## Файлы

- `manifest.json` — неизменяемые условия, время регистрации и контрольная сумма кода;
- `runner.py` — расчёт на стандартной библиотеке Python, без установки пакетов;
- `strategy.md` — исходная замороженная спецификация кандидата;
- `checks.json` — синтетические и математические проверки;
- `state.json` — единственный атомарно обновляемый исследовательский журнал: позиции PAPER, события с первым временем обнаружения, счета, наблюдения, сжатые входные рыночные данные и их SHA. История коммитов сохраняет предыдущие снимки.

Запуск: `python runner.py --state state.json --out next_state.json`. Перед запуском сверить SHA-256 кода с манифестом. После расчёта обновлять только `state.json` через GitHub contents API с текущим blob SHA. Не переписывать main, не менять код/манифест по результатам наблюдения, не переносить сигналы из других тестов.

Автоматизация считается проверенной лишь после фактического выполнения и чтения обновлённого журнала. Созданное расписание само по себе не доказывает успешное исполнение. В случае отсутствия Python/сетевого доступа сообщить TASK_BLOCKED; нельзя имитировать вычисления или заполнять отсутствующие данные.

Во время первого этапа уведомления пользователю — только о новых PAPER-входах/выходах, техническом блокере или итогах этапа. Дубли по одному событию запрещены. На окончании этапа открытая позиция остаётся открытой и оценивается отдельно; принудительное закрытие не выдумывается. Недостаточное число сделок фиксируется как недостаточная выборка.
