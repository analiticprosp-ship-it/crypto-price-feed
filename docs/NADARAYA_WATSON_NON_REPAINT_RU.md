# Nadaraya–Watson: неперерисовывающийся исследовательский контур (22.10.2026)

## Задача
Показывать положение BTC/ETH и материальных альтов относительно центральной линии, верхней и нижней зон NW на закрытых свечах. Встроить в конвергенционный слой "Индикаторы" (4H главная, 1D режим, 1H уточнение) и теневой тест "Спекуляции" (1H главная, 4H режим, 15m уточнение). Никакой независимой торговой команды.

## Оригинальные источники
- https://www.tradingview.com/script/Iko0E2kL-Nadaraya-Watson-Envelope-LuxAlgo/ — версия LuxAlgo, в настройках ОБЯЗАТЕЛЬНО отключить `Repainting Smoothing`.
- https://www.tradingview.com/script/WeLssFxl-Nadaraya-Watson-Envelope-Non-Repainting/ — другое семейство jdehorty с Rational Quadratic Kernel, НЕ тождественно LuxAlgo.

## Фактический GitHub-пилот
Файл `nadaraya-watson-research.json`, script `scripts/build_nadaraya_watson_research.py`. Только `market-structure.json` с реально **закрытыми** OKX USDT-SWAP OHLCV. 15m/1H/4H/1D, монеты BTC/ETH/SOL/SUI/LINK/XRP/BNB/ENA, при наличии 90 непрерывных свечей.

Формула: causal weighted mean over last 50 closed `close`, Gaussian weights `exp(-lag²/(2*8²))`; окно MAE 40 валидных оценок; верх = центр + 3*MAE; низ = центр − 3*MAE. Порог свежести последней закрытой свечи: <= продолжительность ТФ + 20min. Исторические закрытые значения при добавлении новых данных не меняются (при одинаковых свечах/параметрах).

**ПРИНЦИПИАЛЬНО:** это воспроизводимая исследовательская модель с укороченными окнами (50/40), НЕ побарно подтверждённый оригинальный LuxAlgo (его полный endpoint имеет существенно более длинные расчётные окна; точные параметры нужно сверять с конкретной версией Pine). Она не должна называться подтверждённым сигналом LuxAlgo, как и не должна выдаваться за закрытый Pifagor.

Каждое наблюдение включает статус `MODEL_OBSERVED_UNVERIFIED_PARITY`, модель/параметры, время закрытия свечи, оценку центральной линии, верх/низ, наклон, положение цены и события пересечения или возврата. Исключаются незакрытая свеча, временные разрывы, просроченная история, некорректные OHLC, будущие значения и NaN.

Мост `derivatives-observability.json` способен читать этот файл, но помечает `RESEARCH_PROXY_UNVERIFIED`. Даже числовые значения не становятся подтверждёнными Pifagor или LuxAlgo-сигналами.

## Приёмка TradingView — только после неё можно разрешить использовать NW как техническое подтверждение
1. Добавить **Nadaraya-Watson Envelope [LuxAlgo]** от оригинального автора.
2. Установить `Bandwidth = 8`, `Mult = 3`, `Source = Close`, выключить `Repainting Smoothing`.
3. Сверить 1H/4H/1D по BTC и ETH с теми же рынками и временем закрытия: центр, верх/низ и момент возвращения цены внутрь канала.
4. Для точного совпадения привести вычислительные окна Python к выбранной версии Pine или использовать только оригинальные TradingView alerts. При несовпадении НЕ писать `PARITY_VERIFIED`.
5. Для каждого события сохранять время закрытия свечи, версии скриптов, параметры и диапазон исходных данных; минимум 2–3 независимых контрольных прогона.
6. Не включать Nadaraya–Watson в реальную автоматику торгового допуска без отдельного изменения полномочий и разрешения владельца.

Разрешённые статусы: `MODEL_OBSERVED_UNVERIFIED_PARITY` (исследовательское значение), `NO_DATA` (с пропуском/просрочкой), `PARITY_VERIFIED` (только после отдельной документированной проверки; данный пилот этот статус никогда не ставит).

## Исторические ограничения
История `market-structure.json` содержит ограниченный буфер, поэтому полная оригинальная долгосрочная ширина LuxAlgo из него не восстанавливается. Это ограничение качества, а не основание для искусственного backfill. OKX 1D может использовать день биржи с границей UTC+8, это НЕ автоматически тот же ряд, что 1Dutc в TradingView.
