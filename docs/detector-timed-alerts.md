# «Детектор» — точное время сигнала и быстрые уведомления Telegram

## Главное различие времён

1. `signalCandleClosedAtUtc` / `signalCandleClosedAtMadrid`: время закрытия последней 15m-свечи, **на которой ретроспективно подтверждается исследовательская гипотеза**. Это не доказательство, что паттерн существовал раньше внутри свечи.
2. `firstDetectedAtUtc` / `firstDetectedAtMadrid`: **реальное время первой оценки этой комбинации алгоритмом GitHub Actions**, фиксируется при её первой записи. Например: свеча закрылась в 06:15, GitHub запустил расчёт в 06:25 → задержка 10 минут. Время не подменяется временем закрытия свечи.
3. `journalFirstRecordedAtUtc`: когда файл локально сформирован алгоритмом; факт отправки Telegram происходит **после успешного push**, может быть позднее. GitHub queue/network/Telegram latency не гарантируют instant delivery.
4. Первое включение создаёт `BOOTSTRAPPED_NO_ALERTS` и помечает уже существующих кандидатов `initialSnapshotBaseline=true`. Для исторических записей время первого появления неизвестно и не выдумывается.
5. При повторении LONG/SHORT по тому же тикеру в течение 60 минут событие сохраняется, но дополнительное уведомление не отправляется. Обратное направление не подавляется. Сброса всей истории при сбое/повреждении файла нет.
6. Журнал сохраняет до 30 дней записей. Это журнал **наблюдений GitHub**, а не всесторонний исторический backtest.

## Данные и маршрутизация

- `detector-signal-events.json` — отдельный журнал исследований со стабильными идентификаторами по тикеру, направлению и закрытию свечи, со строгим различием временных отметок.
- `detector-candidates.json` — текущие кандидаты с привязанным `signalTiming` и отметками первого обнаружения.
- Workflow `Build Detector SHADOW candidates` запускается после успешного обновления свечей/объёмов; после commit/push запускает `scripts/send_detector_telegram_alerts.py`.
- Telegram-скрипт **не создаёт ордеров**, не подключается к кошельку и не требует биржевых API-ключей. Отправляет только новое `EARLY_CANDIDATE_SHADOW`, а не WATCH/NO_DATA или непроверенные цены входа.

## Подключение на GitHub (без передачи секретов в ChatGPT)

**На данный момент уведомления Telegram НЕ активны до настройки пользователем.**

1. В Telegram создай бота через официальный **@BotFather**, получи bot token, напиши своему боту `/start`.
2. Определи собственный `chat_id` через методы Bot API, не публикуй token и chat_id в чате. Для группы нужно добавить бота в группу и получить идентификатор группы.
3. В GitHub открой `analiticprosp-ship-it/crypto-price-feed → Settings → Secrets and variables → Actions → New repository secret` и создай:
   - `DETECTOR_TELEGRAM_BOT_TOKEN` — токен бота.
   - `DETECTOR_TELEGRAM_CHAT_ID` — идентификатор личного диалога или группы.
4. Повтори ручной запуск `Build Detector SHADOW candidates` только для проверки логики. Уже обнаруженные сигналы **не переотправляются**, а при отсутствии новых будет `NO_NEW_ELIGIBLE_SHADOW_SIGNALS`; поэтому для подтверждения доставки первого сообщения нужна отдельная тестовая отправка через Bot API или новый будущий сигнал. Не стоит создавать искусственный рыночный сигнал ради проверки.
5. Если Telegram secrets отсутствуют, workflow продолжает обычный SHADOW анализ и пишет `TELEGRAM_NOTIFIER: NOT_CONFIGURED` без ложного заявления о доставке. Ошибка Telegram может дать warning/failure шага, но не меняет торговые данные и уже опубликованные сигналы.

## Ограничения

GitHub Actions — периодический сбор (около 15 минут и зависимость от успешных источников), поэтому фактическая отправка **сразу после обнаружения** не означает отправку в момент образования цены. ChatGPT-уведомления доступны отдельно примерно раз в час и не подходят для мгновенной реакции. Более ранние intrabar сигналы не заявлять без реальных intrabar данных.

Если пользователь не хочет Telegram, аналогичный защищённый transport можно заменить почтой, Discord или другим разрешённым каналом. Не просить биржевые ключи, seed-фразы или доступ к средствам.

Ни один webhook не меняет `Спекуляцию`, `Сделка`, риск-политику, `prices.json`, Spot/NAV или Futures orders.
