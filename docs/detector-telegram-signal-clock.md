# Detector: точное время сигнала и Telegram-уведомления

**Статус:** SHADOW / исследование. Уведомления не означают разрешение сделки, не содержат исполнимых цен, плеча, размера позиции и не меняют «Спекуляцию».

## Три разных времени — показываем отдельно

1. `barClosedAtMadrid` / `barClosedAtUtc`: **момент закрытия 15m-свечи**, впервые позволяющей проверить наш сигнал по закрытой свече и трём согласованным 5m-периодам. Это **не** точное внутрисвечное время появления покупателя, разворота или изменения структуры. Более раннее время по этому потоку **не установить**.
2. `firstDetectedAtMadrid` / `firstDetectedAtUtc`: момент, когда GitHub Actions впервые зарегистрировал кандидата `EARLY_CANDIDATE_SHADOW` в `detector-signal-events.json`. Если Github работал поздно, он честно показывает задержку между закрытием свечи и обнаружением.
3. `telegramServerTimestampUtc`: фактическое время сообщения по ответу Telegram, **только после успешного подтверждения API**; хранится в `detector-alert-deliveries.json`. Реальное время прочтения пользователем неизвестно.

Отдельно сохраняется `latestSourceGeneratedAtUtc` (самая поздняя генерация из `market-summary.json` и `detector-rest-flow.json`). Оно не равно времени закрытия свечи или получения уведомления.

**Пример, не реальный сигнал:** свеча закрылась 07:15, источники готовы 07:21, GitHub обнаружил в 07:23, Telegram подтвердил отправку в 07:23:05. Задержка обнаружения 8 минут; время внутри свечи не реконструируется.

## Состояние

- `scripts/detector_signal_events.py` ведёт накопительный журнал первых наблюдений. ID SHA256 от тикера, направления и UTC закрытия 15m свечи; повторы в следующих проходах не создают новое событие.
- При **первом развёртывании** кандидаты считаются `PREEXISTING_AT_FIRST_LEDGER_RUN` и **не отправляются** массовым уведомлением о якобы новых сигналах.
- `scripts/notify_detector_telegram.py` запускается **сразу после успешной публикации** отчёта в GitHub Actions. Он отправляет только `NEW_SHADOW_CANDIDATE`, ещё не подтверждённые в журнале доставок, при задержке **не более 15 минут от первой регистрации**. Старый сигнал не выдаётся за новый.
- Если бота не настроили, задача честно печатает `DETECTOR_TELEGRAM_NOT_CONFIGURED` и не отправляет сообщения. Установленный код **не означает, что Telegram уже подключён**.
- Нет *гарантии* доставки за секунды: GitHub Actions может задерживаться, сетевой Telegram вызов может быть недоступен, уведомления телефона могут быть выключены. Delivery является best effort, по ответу API; при неясном сетевом ответе возможно повторное сообщение, хотя журнал подтверждённых уведомлений защищает от обычных дублей.
- Скрипты используют публичные рыночные данные и Telegram Bot API, не требуют торговых ключей. В репозиторий никогда не записываются токен бота и ID чата.

## Как подключить личный Telegram

1. В Telegram открой **@BotFather**, создай нового бота командой `/newbot`. BotFather выдаст секретный **bot token**.
2. Открой созданного бота и нажми `Start`, иначе бот может быть не вправе отправлять тебе личные сообщения.
3. Узнай числовой `chat_id` **своего** диалога с ботом через Telegram Bot API `getUpdates` в доверенном окружении. Не размещай token в публичных скриншотах, файлах проекта, issue, комментариях или переписке ChatGPT. Для группы/канала нужна отдельная настройка прав и правильного chat ID.
4. В GitHub репозитории `analiticprosp-ship-it/crypto-price-feed` → **Settings → Secrets and variables → Actions → New repository secret** создай:
   - `DETECTOR_TELEGRAM_BOT_TOKEN` — токен от BotFather;
   - `DETECTOR_TELEGRAM_CHAT_ID` — числовой ID выбранного Telegram-чата.
5. Не меняй ключи от бирж и не добавляй `secrets` в код. Проверка после подключения: дождись реально **новой** закрытой свечи, зарегистрированной в `detector-signal-events.json`. Первый существующий кандидат не отправляется задним числом. Сверь `detector-alert-deliveries.json` и `telegramServerTimestampUtc`; без их наличия нельзя говорить «уведомление доставлено».

**Важно:** GitHub Actions может задерживать анализ до следующих запусков сборщиков. Telegram сокращает время **от обнаружения до отправки**, но не от рынка до обнаружения. Для внутрисвечных мгновенных событий понадобится постоянный поток/WebSocket или другой источник с собственной push-обработкой — пока сервер отложен.

## Границы

Это только `EARLY_CANDIDATE_SHADOW` с неоткалиброванным преимуществом, не `BUY_LONG` / `SELL_SHORT` «Спекуляции». Тикеры/направления записаны для исследования; система не отправляет ордера и не говорит, что цена по-прежнему находится в зоне входа.
